# Notes on docs/writing/report_guide.md (2026-11-17)

The guide was drafted by a background agent from the long report style guide and the report
skill, then checked by a fresh reader, which listed 44 passages; most were reworded.

## What was left out of the short guide, and why

- **Rules already in the core rules:** sentence-level writing, context before numbers, where a
  qualification goes, sample size, which stage the work reached, and never inventing.
- **Persuasion goals** ("lead with the achievement", "frame impact as capability unlocked"). They
  belong to portfolio pages, and they conflict with the ruling that accuracy comes first.
- **Detailed rules for other kinds of record:** reference documents, decision records, negative
  findings. Each has one line in the guide's table.
- **Detailed habits for writing a log:** the four-part loop, problem before fix, arguing each point
  once. They are useful, and they would take the guide past 1,000 words.
- **The report skill's procedure:** choosing the type, reading an example, the review passes. These
  are steps in the skill, not rules about the document.
- **Terms specific to the Werewolf project,** so that the guide can be copied elsewhere.
- **Showing a result with and without an outlier.** Dropped for length; worth adding if a rule is
  ever removed to make room.

## Questions for the owner

1. **Corrections in a log.** `CLAUDE.md` says a retracted number is "corrected in place with a
   dated note", and also that a log is not rewritten into hindsight. The guide reads these together:
   a dated note may be added, and the original entry is not rewritten. Is that right?
2. **The negative-finding row** says "without a controlled comparison". That boundary was added so
   that a measured negative result is an experiment report. The long guide does not draw this line.
3. **"Example records the owner has approved."** No list of approved example records exists yet.

## Places where the long guide still contradicts the core rules

These are beyond the ten contradictions already ruled on. The core rules win in each case; the
long guide has not been edited.

1. Its default report outline has an "Iterations" section told in the order of the work. The core
   rules say a report is organised by findings.
2. "Delete the over-specific claim rather than reconciling it." The core rules say a conflict
   between two statements is resolved, not settled by dropping one unchecked.
3. It allows a maxim after an explanation, and its examples of good lessons are maxims. Core rule 3
   does not allow a maxim in place of an explanation.
4. "Frame impact as capability unlocked." Its example states a judgement of quality, which core
   rule 9 replaces with what was observed.
5. "Pull corrections up as findings" conflicts with the report skill's rule that a report mentions
   only the mistakes that changed the method.
6. "Move artifacts into the evidence folder and clean up the originals" conflicts with the data
   layout described in `CLAUDE.md`.
